# Implementation Plan: High-Performance Kubernetes Gateway API Proxy in Rust 2024 ("Traefik-RS" MVP)

This document specifies the technical design, architectural components, dependency choices, and step-by-step roadmap for building a production-grade, minimal working MVP of a high-performance HTTP/HTTPS reverse proxy and Kubernetes Gateway API controller in **Rust 2024 (rustc 1.97)**.

---

## 1. Architectural Overview & System Design

The system decouples the **Control Plane** (asynchronous resource discovery & state reconciliation) from the **Data Plane** (lock-free, zero-allocation request routing & streaming proxying) using atomic swap primitives.

```
                             +-----------------------------------+
                             |     Kubernetes Control Plane      |
                             | (Gateway API, EndpointSlices,     |
                             |  Services, TLS Secrets)           |
                             +-----------------+-----------------+
                                               |
                                     kube-rs (Async Watches)
                                               |
                                               v
+-----------------------------------------------------------------------------------------+
|                                    CONTROL PLANE                                        |
|                                                                                         |
|  +--------------------------+  Reconcile   +---------------------+  Parse PEM / Certs   |
|  | Gateway API Controller   | -----------> | Route Compiler      | -------------------+ |
|  | (kube::runtime::Watcher) |              | (matchit + Filters) |                    | |
|  +--------------------------+              +----------+----------+                    | |
|                                                       |                               | |
|                                           ArcSwap<RouteTable>::store()                | |
|                                                       |                               v |
+-------------------------------------------------------|-------------------+-------------+
                                                        |                   | ArcSwap<CertStore>
                                                        v                   v
+-----------------------------------------------------------------------------------------+
|                                     DATA PLANE                                          |
|                                                                                         |
|   Downstream Client                                                                     |
|          |                                                                              |
|          v                                                                              |
|   [ Tokio TCP Listener (:80 / :443) ]                                                   |
|          |                                                                              |
|          v                                                                              |
|   [ Dynamic SNI TLS (tokio-rustls + ResolvesServerCert) ] <-----------------------------+
|          |                                                                              |
|          v                                                                              |
|   [ Hyper HTTP/1.1 & HTTP/2 Connection Handler ]                                        |
|          |                                                                              |
|          v                                                                              |
|   [ Lock-Free Route Lookup: RouteTable::load() -> matchit::Router::at(path) ]           |
|          |                                                                              |
|          v                                                                              |
|   [ Tower Middleware Pipeline ]                                                         |
|     - Tracing & Access Logging (tower-http::trace)                                      |
|     - Header Filters (Request/Response Header Modifiers)                                |
|     - Rate Limiting / Timeout                                                           |
|          |                                                                              |
|          v                                                                              |
|   [ Upstream Load Balancer (Round-Robin / Random across EndpointSlice healthy IPs) ]    |
|          |                                                                              |
|          v                                                                              |
|   [ Hyper Client: Zero-Copy Body Streaming to Upstream Backend Pod ]                    |
|                                                                                         |
+-----------------------------------------------------------------------------------------+
```

## 4. Detailed Component Design & Data Flow

### 4.1. Core Routing Table (`core/route_table.rs`)
- **Host Matching**: Maps exact hostname (e.g. `api.example.com`) and wildcard hostname (`*.example.com`) to a per-host `matchit::Router<RouteAction>`.
- **Path Matching**: Exact (`/api/v1/users`), Prefix (`/api/v1`), and Regular Expression (where supported).
- **Atomic Swap**:
  ```rust
  pub struct SharedRouteTable {
      inner: arc_swap::ArcSwap<RouteTable>,
  }
  ```
  Data plane threads call `table.load()` acquiring an `Arc<RouteTable>` in single-digit nanoseconds without acquiring any mutex lock.

### 4.2. Upstream Load Balancing (`core/target.rs`)
- Each route action contains a list of backend target endpoints (e.g. `[10.244.1.5:8080, 10.244.2.12:8080]`).
- Supports **Round-Robin** (via atomic integer index modulo targets length) and **Weighted Target Groups** matching Gateway API `backendRefs[].weight`.

### 4.3. Dynamic SNI TLS Engine (`proxy/tls.rs`)
- Implements `rustls::server::ResolvesServerCert`.
- Backed by `arc_swap::ArcSwap<HashMap<String, Arc<rustls::sign::CertifiedKey>>>`.
- When a client issues a TLS ClientHello with SNI `api.example.com`, `ResolvesServerCert::resolve()` looks up the matching certificate in the map (or wildcard cert `*.example.com` or default fallback).
- Kubernetes `Secret` updates reload keys into the map without dropping existing active connections.

### 4.4. Zero-Copy Hyper Proxy Handler (`proxy/handler.rs`)
- For incoming requests:
  1. Extract Host header and URI path.
  2. Perform lookup on `ArcSwap<RouteTable>`. If no route matches, return `404 Not Found`.
  3. Apply Gateway API request filters (e.g. `RequestHeaderModifier`, `URLRewrite`).
  4. Select healthy upstream backend target via load balancing policy.
  5. Rewrite `Uri` to upstream destination (`http://<pod_ip>:<port><path>`).
  6. Forward request body as a continuous stream using `http_body_util::combinators::BoxBody`.
  7. Apply response filters (e.g. `ResponseHeaderModifier`) to upstream response headers.
  8. Stream upstream response body back to downstream client.

### 4.5. Kubernetes Controller & Gateway API Reconciler (`k8s/controller.rs`)
- Watches the following resources:
  - `gateway.networking.k8s.io/v1` `GatewayClass` (filters by `controllerName: "lb.rs/gateway-controller"`).
  - `gateway.networking.k8s.io/v1` `Gateway` (listeners for HTTP :80, HTTPS :443, TLS secret references).
  - `gateway.networking.k8s.io/v1` `HTTPRoute` (hostnames, rule matches, filters, backendRefs).
  - `discovery.k8s.io/v1` `EndpointSlice` (resolves backend service targets directly to Pod IPs to bypass kube-proxy double-hop).
  - `v1` `Secret` (retrieves `tls.crt` and `tls.key`).
- Compiles the aggregated state into a fresh immutable `RouteTable` and dynamic `CertStore`, then triggers `ArcSwap::store()`.
- Updates `HTTPRoute` status condition (`type: Accepted`, `status: True`) and `Gateway` status (`listeners[].attachedRoutes`).

### 4.6. Dual Mode Operation: In-Cluster vs Standalone/Local
- To ensure developer velocity and local testability without needing minikube/k3s:
  - **In-Cluster Mode (`--mode=k8s`)**: Connects to Kubernetes API via in-cluster service account or local kubeconfig.
  - **Standalone Mode (`--mode=standalone --config=routes.yaml`)**: Loads static route specifications from a local YAML file, with auto-reloading file watcher for local development.

## 5. Phased Implementation Steps

### Phase 1: Project Setup & Core Primitives
1. Initialize Rust 2024 Cargo project with all required dependencies (`tokio`, `hyper`, `hyper-util`, `matchit`, `arc-swap`, `tower`, `rustls`, `kube`, `tracing`, `clap`).
2. Implement `core/route_table.rs` with `matchit::Router`, hostname matching, and `ArcSwap` wrapper.
3. Implement `core/target.rs` for upstream endpoints and Round-Robin load balancer.
4. Implement `core/filter.rs` for header modifications and path rewrites.
5. Unit tests for route matching precedence and load balancing.

### Phase 2: Data Plane Proxy Engine (Hyper + Tokio)
1. Implement `proxy/client.rs`: connection-pooling Hyper client for upstream requests.
2. Implement `proxy/handler.rs`: request routing, filter execution, streaming proxying.
3. Implement `proxy/server.rs`: Tokio TCP listener, Hyper HTTP/1.1 and HTTP/2 connection server.
4. Implement `proxy/middleware.rs`: Tower layers for access logging, request timing, and error handling.
5. Integration test: launch proxy against local mock HTTP servers and verify zero-copy streaming, header rewriting, and load balancing.

### Phase 3: Dynamic TLS & SNI (Rustls)
1. Implement `proxy/tls.rs` with `ResolvesServerCertUsingSni` and atomic certificate store swap.
2. Configure Tokio Rustls acceptor on HTTPS port (443).
3. Integration test: verify HTTPS requests with distinct SNI hostnames receive their respective certificates dynamically.

### Phase 4: Control Plane & Kubernetes Gateway API Controller
1. Implement `k8s/gateway_api.rs` with Gateway API CRD definitions and spec structures.
2. Implement `k8s/translator.rs` to transform Gateway, HTTPRoute, and EndpointSlices into `RouteTable`.
3. Implement `k8s/secret_watcher.rs` to fetch TLS certificates and update the dynamic `CertStore`.
4. Implement `k8s/controller.rs` using `kube::runtime::Controller` with reconciliation streams, error backoff, and status condition updates.
5. Provide example Kubernetes manifests in `manifests/` (RBAC, GatewayClass, Gateway, HTTPRoute).

### Phase 5: Observability, Standalone Mode & Polishing
1. Implement Prometheus `/metrics` endpoint (request count, latency histograms, active connections, route count).
2. Implement standalone YAML config loader and file watcher.
3. Add graceful shutdown handling (`SIGINT` / `SIGTERM`) with active connection draining.
4. Performance benchmarking (latency & throughput test script).

## 7. Open Questions & Design Decisions

> [!IMPORTANT]
> **1. Upstream Resolution Strategy: Direct Pod IP (EndpointSlice) vs ClusterIP?**
> - *Recommendation*: Use `discovery.k8s.io/v1` `EndpointSlice` to route directly to Pod IPs, bypassing `kube-proxy` iptables/IPVS overhead and enabling client-side load balancing (Round-Robin/Least-Conn) inside Rust. We will also support ClusterIP as fallback.
>
> **2. Auto-Cert (ACME / Let's Encrypt) in MVP?**
> - *Recommendation*: For the minimal MVP, TLS certs are dynamically sourced from Kubernetes `Secret` resources (which can be managed by `cert-manager` or `instant-acme`). An integrated in-proxy ACME solver can be added as a Phase 2 module to keep the core MVP lightweight and focused.
>
> **3. Data Plane Engine: Pure Hyper vs Pingora?**
> - *Recommendation*: Use `hyper` 1.x + `hyper-util` + `tower` for the MVP. Hyper provides complete low-level control, seamless integration with the Tower middleware ecosystem, smaller binary size, and zero C/FFI dependency issues. Pingora backend adapter can be plugged in as an alternative engine interface later.
